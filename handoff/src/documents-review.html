Product & implementation

A clear brief.
Room to solve it together.

Agreed behavior

Advisor requested, case by case.

The note and link originate in Neoserra’s Next Steps custom field. The client opens the upload from that note. Only a confirmed upload for the matching request can complete the step. Failed or unrelated uploads leave it active.

Recommended approach

Keep the advisor’s action simple.

Use a recognized MySBDC link or structured action. MySBDC handles authentication and opening the widget. Associate the request with the client and exact note version; opening the same link twice should reuse the request. These are proposals for technical review.

Cameron + Emumba to decide

Confirm how the custom field reaches MySBDC, its supported link format, who creates and stores the request, and whether creation happens on note save or first client open. Define request IDs, edits, withdrawal, completion signals, and failure handling.

Signed token
Please confirm the token fields, signing method, expiration, and a server-side example. This is the authentication token in data-token, separate from the advisor’s note.
Domain & release
Send the staging and production hostname requirements, exact DNS records, approved script URL and integrity hash, and any iframe or cross-origin requirements.
Sign-out
Send the supported session-close call, whether we should await it, and how failure should be handled when the client signs out of MySBDC.
Confirmed actions
We need supported upload and download signals with the relevant request, upload or document ID, outcome, and time. An unrelated upload must not clear an advisor’s request.
Document & request status
Confirm how to identify returned documents not yet downloaded, and how an upload is matched when several requests exist. The current “Ready for you” count includes downloaded files.
Supported styling
Confirm the supported theming hooks. This preview uses the theme properties plus CSS inside the open shadow root; the vendor JavaScript is not edited.
