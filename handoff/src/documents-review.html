Your recommendation

What’s the simplest way to show the request in MySBDC and confirm when it’s complete? Cameron, please coordinate the approach with Emumba.

Implementation notes Optional detail for the technical discussion

Proposal: a dedicated MySBDC request component, using Emumba’s request IDs and status where supported. Cameron and Emumba confirm the interfaces; Aaron reviews the client experience. Neither request source is connected in this demo.

Request creation
Confirm whether Emumba supports advisor requests and how MySBDC receives the ID, client/advisor mapping, text, and status. For Neoserra, confirm custom-field access, note versions, and the link/action format. Decide whether it references an existing request or creates one on save or first open. Agree edits and withdrawal; reopening must not create duplicates.
Routing and placement
Client links return to the intended MySBDC request after sign-in, with access checked. Propose how a request sits alongside an unrelated advisor note without duplicate cards or changing the approved next-step priority.
Completion
Confirm upload/download signals with the matching request or document ID, outcome, and time. A click, file selection, failed upload, or unrelated upload must not clear a request. Confirm how to identify returned documents not yet downloaded; the current “Ready for you” count includes downloaded files. The demo does not save next-step completion.
Authentication and release
Agree the data-token fields, signing method, expiry, and server-side example; this token is separate from the advisor note. Confirm staging/production domains, DNS, approved script URL and integrity hash, cross-origin requirements, and the supported sign-out call, including timing and failure handling.
Styling and retention
The supplied vendor JavaScript is unchanged. Confirm supported theming hooks; the preview uses theme properties and CSS in the open shadow root. The widget’s 90-day retention message is sample copy; the policy remains to be agreed.
